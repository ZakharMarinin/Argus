# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Язык

Интерфейс дашборда (шаблоны, тексты в `internal/transport/http/view/view.go` и
`.../view/present.go`, JS в `web/static/js/app.js`) и сообщения об ошибках, которые доходят до браузера
(страница ожидания, тело 500/503-ответов), — на английском: дашборд рассчитан
на англоязычную аудиторию. Значения `AlertTypes`/`AlertSeverities` и их
сентинел `"all"` следуют этому же правилу — их меняет
`internal/transport/http/view/present.go`.

Код, комментарии и серверные логи (`log.Info/Warn/Error` в
`internal/transport/http/handlers`, `internal/app`, а также ошибки в
`internal/config`, `internal/usecase` и `internal/gateway/backend`, которые до
браузера не доходят) остаются на русском. Держитесь этого: смесь
читается хуже, чем любой из вариантов по отдельности.

Данные, которые приходят из базы как есть (`Alert.Message`,
`ContainerStats.LastEventDetail` и подобные), не переводятся — это не текст
интерфейса, а содержимое, записанное collector'ом.

## Что это

Веб-дашборд Argus — self-hosted мониторинга для одного хоста. Это **только
фронтенд-процесс** (`web` из ТЗ): htmx + Alpine.js + raw CSS на Go-шаблонах,
без SPA-фреймворка и без build pipeline.

Техзадание — источник правды по требованиям:
`/mnt/ssd/Users/marin/Documents/Obsidian Vault/Efforts/projects/argus/ТЗ.md`.
Комментарии в коде ссылаются на его разделы (`ТЗ §4.4`, `ТЗ §7`); при правках
проверяйте, что ссылка всё ещё верна.

Второй процесс, `collector`, живёт в соседнем `../argus-backend`. Он владеет
Docker, Telegram, миграциями и базой. Дашборд в Postgres не ходит вовсе:
общаются процессы **только через REST API коллектора `/v1/api`**
(`internal/gateway/backend`). Драйвера базы у дашборда нет.

## Команды

```bash
# Адрес бэкенда - ARGUS_BACKEND_URL из окружения или .env (читается при старте
# и не перекрывает уже заданные переменные); окружение важнее config.yaml.
# Дашборд поднимется и без живого бэкенда - покажет экран ожидания.
go run ./cmd/web

go build ./... && go vet ./... && gofmt -l .
golangci-lint run             # .golangci.yaml общий с ../argus-backend, репозиторий его проходит

go test ./...                                    # без базы: конфиг, рендер, роуты
go test -run TestEmptyDatabaseShowsEmptyStates ./internal/transport/...
go test -run TestTargetStatusAggregatesFromRawProbes -v ./internal/usecase/...
```

Базы у дашборда нет: `go test ./...` не требует ни Postgres, ни живого
бэкенда — тесты `internal/usecase` поднимают `httptest`-сервер, изображающий
`/v1/api`.

Правки в CSS и шаблонах видны по F5 только при `web.template_dir: "./web"` —
иначе они вшиты через `go:embed` и нужна пересборка. Правки в `.go` требуют
пересборки всегда.

## Главное правило

**На экране только то, что есть в базе.** Нет значения — прочерк или пустое
состояние. Мониторинг, подставляющий правдоподобное число вместо
отсутствующего, хуже неработающего, поэтому:

- час без проверок уходит в график как `null` и рисуется разрывом, не нулём;
- цель без единой проверки показывает `—`, а не «100% аптайма»;
- пустая база даёт пустые состояния в каждом блоке, а не демо-цифры.

Это закрыто тестами (`TestEmptyDatabaseShowsEmptyStates`,
`TestMissingValuesRenderAsDash`, `TestLatencyChartKeepsGaps`). Если новая фича
требует данных, которых нет в схеме ТЗ §7, — не выдумывайте колонку и не
подставляйте заглушку: покажите пустоту и опишите пробел в README.

Чего в схеме нет и что поэтому не показывается: CPU/RAM контейнера (у хоста
есть только последний замер из `/v1/api/host`, без истории),
образ контейнера, тип алерта (выводится из вида цели), жизненный цикл алерта
(есть только `sent_to_tg`), latency контейнера (его никто не пингует — на его
странице график совпадений в логах и событий Docker).

**Инциденты выводятся, а не хранятся.** Интервалы простоя (`entity.Incident`)
считаются на чтении: серии неудачных проб, а у контейнеров — `die`/`oom`/`kill`,
закрытые `start`, `restart` или `destroy` (`closesDowntime` в
`internal/usecase/incident.go`). Список закрывающих событий — единственное
место, где это знание живёт; если в watcher'е появится новое событие возврата,
добавлять его нужно туда, иначе вернувшийся контейнер будет вечно висеть
незакрытым.

Одна остановка контейнера — это **несколько** событий Docker: `kill`, затем
`die`, иногда с одинаковой меткой минуты. Поэтому событие падения при уже
открытом интервале не открывает новый, а только двигает последнее
наблюдение: упасть, не вернувшись, нельзя, и пара `kill`+`die` — один простой
(`TestKillAndDiePairIsOneOutage`). Новый интервал начинается только после
записи о возврате.

Вывод интервалов не сортирует переданный слайс на месте — он копирует.
Иначе лента событий на странице контейнера, разложенная новыми сверху,
перетряхивалась бы выводом инцидентов и показывала самые старые записи
(`TestIncidentDerivationKeepsEventOrder`).

Третье состояние, `IncidentUnclosed`, остаётся для падения, после которого
записи о возврате нет вовсе: начало показывается, длительность — прочерк, в
сумму простоя он не попадает, а его число стоит в подписи блока. Не заменяйте
его на «лежит до сих пор»: счётчик, растущий у работающего контейнера, —
ровно то вранье, которое запрещает главное правило
(`TestUnclosedOutageHasNoDuration`, `TestContainerDieWithoutReturnHasNoDuration`).

По той же причине продолжающийся простой пробы считается до последней
неудачной проверки, а не до `time.Now()`: если collector перестал проверять,
длительность не должна расти сама (`TestProbeIncidentStaysOpenUntilLastFailure`).

**Сводка — триаж, история — на `/history/*`.** На сводке нет длинных
списков: алерты, совпадения в логах и простои живут на вкладках истории по 50
строк. Поллится только первая страница истории (`TestHistoryPagerPausesPollingOnOlderPages`),
и чип свежести на странице без поллинга не кричит «нет связи». Не
возвращайте ленты на сводку — туда идёт только Recent activity (8 строк,
от warning и выше).

**Алерты и совпадения читаются с `order=desc`, `skip`, `since` и
`X-Total-Count`** (`fetch` в `internal/gateway/backend`). Старый бэкенд эти
параметры игнорирует и отдал бы самые старые записи как свежие, поэтому
возрастающие id или отсутствие `X-Total-Count` — это `entity.ErrBackendTooOld`:
настоящая ошибка (500), а не экран ожидания (`TestOldBackendIsARealError`).

**Маскот один.** Настроение — самый тревожный сигнал из упавших целей,
алертов, предупреждений и порогов совпадений в логах (`view.LogMood`:
0 / 1–2 / 3–4 / 5+), а строка под ним называет победивший сигнал
(`TestMoodTakesWorstSignal`). На карточках контейнеров гифок нет. Легенда
настроений — `<details>` внизу сайдбара.

Фон суточной полосы на странице контейнера — `idle`, а не `up`: события
Docker говорят только о падениях, и промежуток без них не доказывает, что
контейнер работал.

## Архитектура

Поток данных однонаправленный, каждый слой знает только соседа. Раскладка
повторяет `../argus-backend`: домен в центре, зависимости смотрят
внутрь.

```
cmd/web                       флаги, логгер, сигналы
  └─ internal/app             App (сервер, остановка) + Container (сборка зависимостей)
      └─ internal/transport/http
          │   router          маршруты и раздача статики
          │   handlers        страницы, партиалы, JSON-точки; порт UseCase
          │   view            Presenter + модели представления + рендер шаблонов
          └─ internal/usecase Агрегаты (аптайм, рестарты, p95); порт Backend
              └─ internal/domain/entity   доменные типы и ErrNotReady/ErrNotFound
                  ↑
internal/gateway/backend      HTTP-клиент argus-backend: DTO → entity
web/                          templates + static, вшитые через go:embed
```

Порты объявляет тот, кто ими пользуется: `handlers.UseCase` — в handlers,
`usecase.Backend` — в usecase. Поэтому `usecase` не знает про HTTP, `entity`
не знает ни про HTTP, ни про HTML, а JSON бэкенда и микросекунды латентности
не выходят за `internal/gateway/backend`.

Пакет `web` — только `go:embed` ассетов: пересборка нужна, если менять
шаблоны без `web.template_dir`.

Дашборд почти ничего не пишет. Пишущих ручек ровно две, и обе про
uptime-таргеты: `POST /targets` (форма «New target» → `POST /v1/api/targets`)
и `DELETE /targets/{id}`. После успеха они шлют `HX-Trigger: refreshNow`,
чтобы список целей обновился сразу. Остальное - только GET и только чтение
из бэкенда. Новую запись в бэкенд не добавляйте без явного решения.

## Приёмы, которые легко сломать по незнанию

**Партиалы подменяют сами себя.** Каждый партиал рендерит собственный корневой
элемент вместе с его `hx-get`/`hx-trigger` и меняется через `outerHTML`.
Страница вызывает `{{template "targets" .Targets}}` — и всё. Если убрать
`hx-get` из партиала, поллинг умрёт после первого свапа. Это проверяет
`TestPartialsReemitTheirPolling`.

**График живёт вне поллинга.** Карточку с графиком htmx не трогает: пересоздание
`canvas` каждые 10 секунд убивало бы анимацию и подсказки. Точки приходят
отдельным JSON-запросом раз в минуту, датасеты обновляются на месте.
Не заворачивайте её в партиал.

**Ошибки разделены намеренно.** `entity.ErrNotReady` (argus-backend не
отвечает, таймаут или его схема ещё не готова) —
штатное состояние: страницы отдают 503 с экраном ожидания, партиалы 503 **без
тела**, чтобы htmx оставил на экране последние живые данные. Любая другая
ошибка — 500 и в лог. Не сваливайте всё в экран ожидания: баг в запросе тогда
выглядит как «база не готова» (`TestRealErrorIsNotHiddenBehindWaiting`).

**Статусы — через CSS-переменную.** Класс `is-up`/`is-warn`/`is-down`/
`is-idle` задаёт `--s`; точка и пилюля читают её и не знают, какой именно
статус на них висит. На тёмных панелях (`.card--dark`, `.ctn-card--dark`,
`.alert-row--dark`) тот же `--s` подмешивается к белому через `color-mix` —
иначе статусный цвет теряет контраст. Цветов в шаблонах нет — новый компонент
должен читать переменные, а не хардкодить hex.

**Тема — атрибут, а не media-query.** Синхронный скрипт в `<head>` разрешает
системную тему в конкретный `data-theme` до первой отрисовки. Благодаря этому
тёмная палитра описана в CSS ровно один раз (`:root[data-theme="dark"]`), без
дубля под `prefers-color-scheme`, и страница не мигает светлым. Скрипт обязан
оставаться инлайновым и стоять до `<link>` на стили
(`TestThemeIsResolvedBeforePaint`).

**Анимируется изменение, а не свап.** Партиал подменяет себя каждые 10 секунд
независимо от того, пришло ли что-то новое, поэтому вешать анимацию на сам свап
нельзя: экран, который мигает без повода, приучает на себя не смотреть. `app.js`
на `htmx:beforeSwap` сравнивает `textContent` ответа с тем, что уже на экране, и
вешает `.is-fresh` только на реальную разницу. Сравнивается текст, а не
разметка: Alpine дописывает в DOM свои атрибуты, и по HTML карточка
«менялась» бы каждый тик.

По той же причине переходы на данных внутри партиалов бесполезны — элемент
заменяется целиком, и `transition` на новом элементе не играет. Анимируем то,
чем управляет пользователь (наведение, нажатие), и `.is-fresh`.

**Alpine — только локальные интеракции**: пауза поллинга, счётчик свежести,
модалка, сворачивание сайдбара, переключатель темы. Данные приносит htmx;
состояния приложения в JS нет.

Группа контейнеров и легенда настроений в сайдбаре — исключение и не на
Alpine: это `<details data-remember="ключ">`, у которого состояние, клавиатура
и aria уже есть в браузере. В `app.js` остаётся только память о раскрытии
(localStorage, как у темы). Восстановление
вызывается сразу при выполнении `app.js`, а не по `DOMContentLoaded`: скрипт
подключён с `defer` и выполняется к `domInteractive` — это заметно раньше первой
отрисовки, поэтому свёрнутая группа не успевает мигнуть раскрытой.

**Всё вендорится.** htmx, Alpine, Chart.js и шрифты лежат в `web/static/` и
вшиты в бинарник: дашборд должен открываться на хосте без интернета (ТЗ §4.4).
Не добавляйте ссылок на CDN — это ловит `TestStaticAssetsEmbedded`.

## Стиль, который навязывает линтер

`.golangci.yaml` скопирован из `../argus-backend`, чтобы репозитории одного
проекта не разъезжались. Из него вытекают два правила, о которых легко забыть:

- `noinlineerr` — никаких `if err := f(); err != nil`. Сначала присваивание,
  потом проверка.
- `nlreturn` — пустая строка перед `return`, `break` и `continue`, если это не
  первый оператор блока.

Неизменяемые таблицы уровня пакета (`Moods`, `AlertTypes`, `months`, `pages`)
внесены в исключения `gochecknoglobals`: Go не умеет const-мапы. Новую
глобальную переменную под это исключение не подводите — заведите поле в
структуре.

## Шрифты

Семейств ровно два, и третьего быть не должно: **Inter** (`--font-sans`) —
весь текст, от заголовков до подписей, **JetBrains Mono** (`--font-mono`) —
данные, логи, адреса и код. Названные в макете Bricolage Grotesque и Plus
Jakarta Sans не содержат кириллицы и отброшены вместе с отдельным
display-шрифтом: на такой плотности экрана третий голос только мешал.

Оба вендорены в `web/static/fonts/` подсетами latin/latin-ext/cyrillic/
cyrillic-ext. Прежде чем менять шрифт, проверьте, что у него есть
кириллический subset.
